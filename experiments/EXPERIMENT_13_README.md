# Experiment 13 — multi-seed repeat of the Experiment 11 grid

Experiment 11 ran every configuration with one seed. Experiment 13 repeats the same grid with many
seeds, using the real C sampler:

- How stable is throughput across seeds?
- Do seed-averaged goodness-of-fit results match the exact predictions of Experiment 12?

Configurations that passed with seed 1 may fail with other seeds, and the reverse.

- **Grid:** the same as Experiment 11. Classical and Trapezoid at H = 0–4, T = 0–4,
  N = 8, 16, 32, 64, 128, 256 (150 Trapezoid + 6 Classical configurations).
- **Performance:** seeds 1–5, 5 repetitions each, 2^25 samples after a 100,000-sample warm-up.
  Each run is a separate process pinned to isolated CPU 7, with run order shuffled per seed and
  repetition. The uniforms are precomputed xoshiro256+ (a 2 GiB buffer), so PRNG work is excluded
  from timing. The buffer exists for one seed at a time and is deleted when that seed is finished.
- **Validation:** seeds 1–30 on every configuration, Classical included as the control, so
  4,680 runs. Each run tests the full 2^25 stream with Chi-square, KS, CvM and AD against
  N(0,1) at alpha = 0.05, using the same bins as Experiments 10–12. Validation uses inline
  xoshiro256+, which produces exactly the same stream as the precomputed buffer without needing
  a 2 GiB file per seed. The `checksum_matches_performance` column confirms this for seeds 1–5.
- **Output:** CSV files only. Raw Gaussian samples are never written to disk. The analysis and
  report are in `reports/experiment13/`, regenerated by
  `reports/experiment13/analysis/analyze_experiment13.py`.

Files: `experiments/experiment13.py` (driver; reuses the run, logging and test code of
`experiment11.py`) and `experiments/experiment13.yaml` (configuration).

## 1. Before the real run

From the repository root:

```bash
cd ~/projects/Ziggurat-Inspired-Method-for-Efficiently-Generating-Gaussian-Random-Numbers-in-Hardware
make -C c CC=gcc O2                     # only if c/benchmark is missing; do not rebuild mid-experiment
cat /sys/devices/system/cpu/isolated    # must show 7
cat /sys/devices/system/cpu/cpufreq/boost                     # must show 0 (boost off)
cat /sys/devices/system/cpu/cpu7/cpufreq/scaling_max_freq     # 3200000 = 3.2 GHz cap
```

- **CPU isolation:** set up as in `EXPERIMENT_11_README.md`, section 2, which is unchanged.
- **Boost check:** the script refuses to start timing unless CPU 7 is isolated and boost is 0
  (`performance.require_boost`).
- **Governor (optional):** to also require a governor, set `performance.require_governor`, for
  example `performance`, and set it first with
  `echo performance | sudo tee /sys/devices/system/cpu/cpu7/cpufreq/scaling_governor`.
- **Closing other programs:** close the browser, IDE and other heavy programs before timing.

**Throughput isn't comparable with Experiment 11.** Experiment 11 ran with boost on, at about
4.3 GHz; this run is at 3.2 GHz. Compare `speedup_vs_classical` ratios, not M samples/s, across
the two experiments.

## 2. Run

```bash
.venv/bin/python -B experiments/experiment13.py --dry-run     # plan and rough runtime, runs nothing
nohup .venv/bin/python -B experiments/experiment13.py > experiment13.log 2>&1 &   # timing, then validation
tail -f experiment13.log                                      # watch progress
```

| Option | Meaning |
|---|---|
| `--config FILE` | Use another YAML file (default `experiments/experiment13.yaml`). |
| `--phase performance` | Timing only. |
| `--phase validation` | Validation only. Use with `--resume` on an existing output directory. |
| `--resume` | Continue an existing output directory, skipping work already marked `ok` and retrying failures. |
| `--output-dir DIR` | Write somewhere other than `output_dir`. |
| `--dry-run` | Print run counts, a rough runtime and example commands, then exit. |

**Interruptions.** Every row is written to disk immediately, so if the run is interrupted or the
machine reboots, restart it with `--resume`. A resumed run must use the identical configuration
file; the script checks this against the saved `config.yaml`. Only one process can use an output
directory at a time.

**Runtime.** About 3.4 h at Experiment 11 speed, and up to about 4.6 h at 3.2 GHz:

- Timing: 3,900 runs of about 1.2 s each.
- Validation: 4,680 runs of about 7 s each, with 4 workers.

**Disk and memory.** Disk: at most one 2 GiB uniform cache at a time, in the system temp
directory, deleted after each seed. Memory: each validation worker holds the
256 MiB sample array plus test overhead, which is less than Experiment 11 because there is no buffer
to load.

**Smoke test** (seconds; all of this was checked before handover). Copy the YAML, change
`layers: [8]`, `heads: [0, 1]`, `tails: [0]`, `samples: 2000`, `warmup: 1000`,
`uniform_buffer_bytes: 1048576`, `performance.seeds: [1, 2]`, `repetitions: 2` and
`validation.seeds: [1, 2, 3]`, then run:

```bash
.venv/bin/python -B experiments/experiment13.py --config /tmp/smoke13.yaml --output-dir /tmp/e13smoke
```

The warm-up must fit in the buffer: 100,000 warm-up samples need more than a 1 MiB buffer.

## 3. Configure (`experiments/experiment13.yaml`)

| Key | Default | Meaning |
|---|---|---|
| `output_dir` | `experiments/results/experiment13` | Output location, relative to the repository root. |
| `binary` | `c/benchmark` | Benchmark executable. |
| `prng` | `xoshiro256plus` | Fixed. |
| `uniform_buffer_bytes` | 2147483648 | Precomputed buffer per seed (performance phase). |
| `cache_dir` | `null` | Directory for the temporary uniform cache (null = system temp). |
| `layers`, `heads`, `tails` | 8–256, 0–4, 0–4 | The grid, as in Experiment 11. |
| `include_classical` | `true` | Classical at each N; the baseline for `speedup_vs_classical`. |
| `samples` | 33554432 | Samples per run (2^25), as in Experiments 10–12. |
| `warmup` | 100000 | Warm-up samples for timed runs, outside timing; the stream resets to the seed afterward. |
| `performance.seeds` | 1–5 | Seeds for timing. Timing barely depends on the seed. |
| `performance.repetitions` | 5 | Timed repetitions per configuration per seed. |
| `performance.cpu` | 7 | CPU used by `taskset` for every timed run. |
| `performance.require_isolation` | `true` | Refuse to time unless that CPU is isolated. |
| `performance.require_boost` | 0 | Refuse to time unless boost has this value; `null` disables the check. |
| `performance.require_governor` | `null` | Optional governor check; recorded either way. |
| `performance.shuffle_seed` | 2026 | Base of the reproducible shuffled run order. |
| `validation.seeds` | 1–30 | Seeds for goodness of fit. Seed 1 repeats Experiment 11. |
| `validation.include_classical` | `true` | Classical as the control. |
| `validation.uniform_mode` | `inline` | `precomputed` also works but needs a 2 GiB cache for every seed at once. |
| `validation.workers` | 4 | Parallel validations on the non-isolated CPUs. |
| `validation.significance_level`, `validation.chi_square` | 0.05; 100 bins over [−5, 5] + 2 tails | Same as Experiments 10–12, so Experiment 12's predictions apply directly. |

To extend to more seeds later, for example 31–100, use a new output directory (`--output-dir`) with
a config that lists only the new seeds, then concatenate the CSV files.

## 4. Output files (`experiments/results/experiment13/`)

| File | Contents |
|---|---|
| `performance_runs.csv` | One row per timed process (same columns as Experiment 11). |
| `performance_summary.csv` | One row per configuration and seed (as in Experiment 11). |
| `performance_summary_all_seeds.csv` | One row per configuration: pooled median throughput, mean, sd, minimum and maximum of the per-seed medians, and `speedup_vs_classical`. |
| `validation_results.csv` | One row per configuration and seed (same columns as Experiment 11). |
| `environment.csv` | Machine state, including boost, governor, frequency, isolation and binary hash. Recorded at session start, after each performance seed, and at session end. |
| `config.yaml` | Copy of the configuration used. |

Column meanings are listed in `EXPERIMENT_11_README.md`, section 5. Experiment 13 differs in two
columns:

- **`checksum_matches_performance`:** 1 when the validated (inline) stream equals the timed
  (precomputed) stream. It is empty for seeds 6–30, which were not timed.
- **`stream_sha256`:** for seed 1, this should equal Experiment 11's value for the same
  configuration, giving a bit-for-bit reproducibility check.

## 5. What to compare with Experiment 12

For each configuration over the 30 seeds:

- **Mean χ² excess:** `chi2_statistic − chi2_degrees_of_freedom` should be close to `lambda_pred`
  in `experiments/results/experiment12/model_validation_all.csv`. The standard error is
  √(2(101 + 2λ)/30), about 2.6 when λ is small.
- **χ² rejection rate:** should be close to `p_reject_chi2`. Use a binomial interval, about ±0.08
  at 30 seeds near p = 0.05.
- **Classical:** mean excess near 0, rejection rate near 5% per test, p-values roughly uniform.

**Identical streams across configurations.** Configurations that never reach their deeper head or
tail levels within 2^25 samples produce identical streams. Their `stream_sha256` is equal, so they
are not independent results; group by `stream_sha256` before counting.
